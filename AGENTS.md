# Пам'ять проєкту

## Деплой

- **При будь-яких змінах — пуши їх на тестовий environment** (Netlify, сайт `tavriya-schedule-live`): `netlify deploy --prod`.
- Це стосується лише тестового деплою. **Не комить і не пуш у git без окремого прохання користувача** — це не входить у правило.
- Прод (Render, SSH-сервер) не деплоїмо без окремого дозволу користувача.
- Деталі середовищ і команд — у [DEPLOYMENT.md](DEPLOYMENT.md).

## Таблиці Google Sheets — КРИТИЧНЕ ПРАВИЛО

**Prod і тест мають РІЗНІ таблиці. Перплутати їх = прод показує студентам неправильний розклад (це вже ставалося).**

- **Prod-таблиця** — єдина для Render і КФКМГ (SSH). Її URL мають містити `.env`, `client/.env` і змінна в Render dashboard. URL: `https://docs.google.com/spreadsheets/d/1pl0PFC1...ULQ/export?format=csv&gid=0` (повний — у DEPLOYMENT.md).
- **Тестова таблиця** — тільки для Netlify. Її URL заданий через `netlify env:set VITE_GOOGLE_SHEETS_URL ...` (усі контексти). У локальних `.env` її НЕ прописуємо.
- **НЕ міняй `VITE_GOOGLE_SHEETS_URL` у локальних `.env` на тестову таблицю** — з локальних `.env` збирається prod-деплой на КФКМГ (`deploy.ps1`).
- Після будь-якого деплою **перевіряй, який URL реально зашит у задеплоєному бандлі**: `grep -o 'docs.google.com/spreadsheets/[^"]*' assets/index-*.js` (локально в `dist/` або на сервері). Для Netlify — те саме на задеплоєному бандлі.
- Зміни розкладу вносить користувач у prod-таблицю. Якщо prod і тест показують різні дані — перш за все перевір, чи не читають вони різні таблиці.
